## Proposed plan (awaiting your approval)

### 1. Parser hardening — `src/mobile/testEngines/iperf3CommandParser.js`
- Split **`errors`** (block apply) vs **`warnings`** (info only).
- Hard errors: empty command, missing `-c` / `--client`, port token with no digits (after normalize).
- Add **`normalizePort(value, fallback = "5201")`** — always returns a valid numeric string; never `NaN`/empty in output.
- Keep compact + long-flag support; manually verify these three commands:
  1. `iperf3 -c 10.10.10.20 -p 5201 -t 15 -P 4 -R -J`
  2. `iperf3 -c 10.10.10.20 -p5201 -t15 -P4 -R -J`
  3. `iperf3 -c customer.server.com --port 5202 --time 30 --parallel 8 --reverse --json`
- Set `ok: true` only when no hard errors and client host is present.
- Missing `-J` → soft warning only (BabyDragon adds JSON at execution in 1G4B).

### 2. Page behavior + compact UI — `src/mobile/rf/pages/Iperf3TestPage.jsx`
- **`applyCustomerCommand`:**
  - If `parsed.ok` → merge parsed values + show green/success message.
  - If fail → show clear error message; **do not call `update()`** (keep previous valid settings).
  - Keep command textarea text as typed.
- Add **`displayPort(port)`** helper for quick strip + server note (never show `NaN`).
- **Binary badge:** map plugin statuses to:
  - **Ready** = `status.ok === true`
  - **Missing** = `binary_missing`, `binary_missing_or_copy_failed`, or not yet checked
  - (Optional: treat `plugin_error` as “Missing” with a one-line plugin hint in summary.)
- **Shorten copy:**
  - Header subtitle → one line about setup-only (no execution).
  - Footer notes → exactly:
    - `Customer server: iperf3 -s -p 5201`
    - `Place ABI binary under android/app/src/main/assets/iperf3/<abi>/iperf3`
  - Remove “Now/Next Step 1G4B” from the page body (monitor note in Core can stay).
- Optional: add `bd-rf-iperf3-parse-error` class on failed parse message.

### 3. CSS polish — `src/mobile/mobile.css`
- Style parse error vs success messages.
- Tighten note/footer spacing if needed after copy trim.
- No broad RF/CSS rewrites.

### 4. Config touch (optional) — `src/mobile/rf/config/dataTestConfig.js`
- Shorten iPerf test-type description only if you want UI consistency.

### 5. Core verification only — `src/mobile/rf/MobileRfKpiCore.jsx`
